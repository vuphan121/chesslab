# Changes — 2026-09-23

This record summarizes the Opening Study redesign and the reliability fixes completed and verified
on 2026-09-23.

## Opening Study interface

- Kept the original Chesslab top bar and moved it flush to the top edge on every main page.
- Rebuilt the repertoire picker around a compact, expandable layout that can handle many
  repertoires. Selecting a repertoire selects all chapters by default; each chapter can then be
  selected, deselected, or expanded to preview its lines.
- Repertoire choices show their chapter count and a white/black piece-color marker. The old total
  selected-line summaries were removed. Mixed training also has no total-line count.
- During a drill, the board is centered and scales against both viewport width and height. The move
  panel stays on the left without overlapping the board, and the Back button sits directly below
  the top bar at the left edge.
- Next line, Do it again, and Analyze sit immediately to the right of the board on desktop. The
  completion action that best matches the result is emphasized without hiding the alternatives.
- Feedback is a large bottom-right status card and says only `Correct` or `Incorrect`; the board
  arrow identifies the move. Hint arrows are slightly smaller than before.
- The repertoire and chapter names live in the move panel instead of the top bar. The board flip
  control was removed from this page. Narrow screens use a stacked layout.

## Reliability and correctness

- Reset and PGN loading now use the same request-generation guard as other game actions, preventing
  stale responses from restoring an old board.
- Stockfish now stops and drains interrupted searches. A process that exits or fails to stop is
  replaced automatically before another analysis is used.
- Trainer staleness decay uses each box's real review gap, and persisted box values are clamped.
- Login rate limiting uses the originating address supplied by Render's proxy, with fallbacks.
- Repertoire construction rejects invalid sides and prevents a transposed move from being both
  accepted and excluded; an accepted occurrence wins.
- Coach analysis rejects malformed FEN before querying an evaluation provider.
- The chess engine detects threefold repetition on the active move-tree path and recognizes any
  number of same-color bishops against kings as insufficient material.
- Authentication changes synchronize across browser tabs, and repeated set/clear operations are
  idempotent.
- Threefold-repetition identity now includes an en-passant target only when the capture is legal;
  a pinned adjacent pawn no longer prevents an otherwise valid repetition draw.
- Position changes cancel in-progress board drags so stale pointer state cannot leak into the new
  position.
- Sidecar exclusions reject ambiguous duplicate chapter names instead of silently modifying the
  first match.
- Expandable line previews use stable content identities across catalog refreshes, clear stale hover
  previews, and retain expansion only for lines that still exist.
- The redundant `Line so far` heading was removed from the drill move panel.

## Verification

- Full Go suite passed under the race detector.
- The affected Go packages passed 20 consecutive runs.
- Real Stockfish tests passed for forced process death and stop/drain isolation.
- All 29 frontend tests, ESLint, TypeScript checking, and the production Next.js build passed.
