# Changes — 2026-09-29

This pass hardened the browser-local game and analysis paths after the Analysis Board and Study from
Book moved away from server-held game state.

## Correctness and lifecycle fixes

- Local games now detect threefold repetition with legal en-passant normalization, reject moves after
  any terminal result, and keep the halfmove clock in analysis cache keys so 50-move-rule positions do
  not share an incorrect result.
- Pending board animations own their timeout callbacks. Completion or watchdog timers from an older
  move cannot clear a newer animation, and timers are removed when the board unmounts.
- Study from Book owns its `LocalGame` per hook instance instead of sharing module-global mutable state.
  Analysis is tied to the displayed FEN, stale saved-line responses cannot overwrite user play, and
  tablebase results render through the same result path as engine evaluations.
- Opening Explorer data is cleared or shown as loading during a position change, avoiding stale rows
  and layout jumps while the next position loads.

## Performance and request behavior

- `LocalGame` has an ID-to-node index for constant-time navigation. Move-tree snapshots use immutable
  structural sharing and rebuild only an edited branch's ancestor path rather than recursively cloning
  the entire tree on every move or navigation.
- Opening Explorer caches by the four position-defining FEN fields, so transpositions with different
  move clocks reuse the same response.
- Cloud evaluation, tablebase, and Explorer requests now have subscriber-counted cancellation. Rapid
  navigation aborts obsolete network work without cancelling a shared request that another consumer
  still needs.
- Move-history cloud evaluations are merged into React state as one batch; slower browser-Stockfish
  fallbacks are committed in small batches and do not compete with foreground analysis.
- Book Study serializes its history evaluator behind foreground analysis, preventing two Stockfish
  workers from competing for CPU during an interactive search.

## API change

`GET /api/position-evals?fens=...` was replaced by:

```http
POST /api/position-evals
Content-Type: application/json

{"fens":["<full FEN>", "<full FEN>"]}
```

The JSON body avoids browser and proxy URL limits. Database lookups are still deduplicated by the
clock-stripped position key, but the response includes an entry for every distinct full FEN supplied,
including repeated positions with different clocks.
