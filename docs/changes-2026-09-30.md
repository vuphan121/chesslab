# Changes — 2026-09-30

This pass reduced Opening Study startup/network work, preserved complete mobile offline caches, and
removed several remaining long-session and lifecycle costs.

## Opening Study and offline behavior

- Phone-sized clients now start one shared, idle-scheduled background job that caches every
  repertoire, progress map, and the full dated Today queue. It continues after the picker unmounts,
  including while the user is drilling, and retries when the browser comes back online.
- Today's Training now rotates its cached FIFO queue locally on mobile. Offline completions are
  written to a typed persistent outbox with stable operation IDs and replayed in order on reconnect.
  The server records each ID transactionally, so a lost response cannot advance the same line twice.
- Catalog, progress, and explicit refresh callers share in-flight requests. A cached network-first
  read that times out releases its registry slot so a later request cannot attach to a dead promise.
- Login refreshes the application shell; the mobile cache owner handles the full catalog. The manual
  Settings refresh still forces the entire catalog, settings, progress, and shell refresh.
- Offline-store ownership is changed only after IndexedDB clearing succeeds, preventing cached data
  from a previous login being relabeled for a new user after a storage failure. Login now fails closed
  when that clear fails instead of continuing with the new account.
- Cache write generations stop late network responses from overwriting a newer Today rotation or
  refresh. Timed-out requests remove only their own in-flight slot, and both typed outboxes drain work
  added while a flush is already active.
- Forwarded client-IP headers are ignored unless `TRUST_PROXY_HEADERS=true`; the Render blueprint opts
  in explicitly, while direct/local deployments remain spoof-resistant by default.
- The service worker cache moved to v3 and prunes old, unreferenced hashed Next.js assets while keeping
  a small grace set for concurrent refreshes, preventing silent growth across deployments.

## Today’s Training payload

`GET/PUT /api/today-training` and `POST /api/today-training/advance` now return:

```json
{
  "settings": { "repertoireIds": ["..."] },
  "entryCount": 900,
  "nextEntry": { "repertoireId": "...", "cardId": "..." }
}
```

The server still owns and validates the canonical FIFO queue, but routine desktop reads and advances
only return its count and front entry. For the current 900-entry queue this reduced each routine
response from about 95 KB to 332 bytes. Mobile downloads the full queue once through
`GET /api/today-training/snapshot`, then advances locally without a per-line download. Concurrent
frontend reads are coalesced.

## Board and analysis performance

- Move-tree flattening is cached by immutable root, so navigation reuses the same ID index. Active
  line construction is linear instead of repeatedly prepending nodes.
- Cloud/tablebase caches ignore only the irrelevant FEN fullmove number and retain the halfmove clock.
  Narrow analysis callers can subscribe to an equal or wider in-flight MultiPV request, and a late
  narrow result cannot overwrite a wider cached result.
- Board interaction state is position-keyed and reducer-driven. Position changes clear annotations,
  promotion, and drag state atomically without calling state setters during render. Navigation piece
  movement uses the Web Animations API.
- Authenticated content renders immediately with default piece settings while cached/network settings
  load asynchronously instead of showing a blank page for up to 1.5 seconds.

## Opening Study PGN export

The existing **Export PGN** control keeps the same wording, but copies the generated PGN to the
clipboard rather than downloading a `.pgn` file. It uses the Clipboard API with a legacy copy fallback.
